# Blender depth workflow

The versioned template is
`blender/template/k2lab_depth_template_v1.blend`. It contains a calibrated
perspective camera, metric scale, a poseable armature mannequin, bed, chair,
table, sofa, floor, wall, and named collections. The geometry is generated by
`blender/create_template.py`; it uses no third-party asset and is released as
CC0-1.0.

Open the template, pose the mannequin in Pose Mode, transform or replace the
furniture, and frame the scene through `K2Lab_Camera`. Geometry and occlusion
matter; photorealistic materials do not.

Export:

```bash
blender blender/template/k2lab_depth_template_v1.blend \
  --background --python blender/export_scene.py -- \
  --output reports/my-scene --width 1024 --height 1024
```

The exporter forces a one-sample CPU Cycles data render so headless and desktop
Blender expose the same Z and object-index passes. It writes:

```text
depth_16bit.png
depth_preview.png
object_ids.png
masks/*.png
camera.json
objects.json
export.json
scene.blend
```

`depth_16bit.png` is a true 16-bit grayscale PNG normalized from camera
`clip_start` to `clip_end`, near white and far black. Camera metadata declares a
top-left image origin and no vertical flip. The asymmetric objects in the
`Calibration` collection make accidental horizontal or vertical mirroring easy
to spot.

K2Lab only requires `depth_16bit.png`. Bundle metadata and masks are optional
future-compatible inputs. The shared bundle loader verifies the depth checksum,
resolution, version, and depth convention before accepting a directory.

The reference export in `reports/blender-reference` was rendered twice with
zero differing depth or object-ID pixels. PNG container hashes can differ
between Blender writes; the manifest always hashes the exact files from its own
export.
